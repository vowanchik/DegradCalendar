# PartyUp

Игровые встречи с друзьями: отдельное приложение Windows и мобильные приложения Android / iOS. Общий интерфейс на React + TypeScript; Electron на Windows, Capacitor с нативным Java / Swift на телефонах. Это приложения с WebView, а не Flutter/SwiftUI-интерфейс. Сервер — Node.js 24, SQLite, без обязательной подписки на базу данных.

## Скачать готовое приложение для Windows

**[Скачать PartyUp 0.1.1 для Windows 10/11 x64 (.exe)](https://github.com/vowanchik/DegradCalendar/releases/download/v0.1.1/PartyUp-0.1.1-Windows.exe)** · [Все релизы](https://github.com/vowanchik/DegradCalendar/releases)

Готовая portable-сборка запускается без установки Node.js, pnpm или сборки исходников. Сохраните `.exe` в постоянную папку и откройте его. Если предыдущая версия уже запущена, завершите её через значок PartyUp в трее → «Завершить работу».

На экране входа укажите адрес общего сервера вашей компании друзей и войдите или зарегистрируйтесь. Адрес сообщает тот, кто разместил сервер; самостоятельный запуск сервера описан ниже. Windows-клиент не включает сервер. Опубликованная версия 0.1.1 требует HTTPS для удалённого сервера. В исходниках версии **0.1.2** добавлен HTTP по IP с предупреждением о передаче данных без шифрования; для него нужна новая сборка.

Файл пока не подписан сертификатом издателя. Контрольная сумма SHA-256 опубликована рядом с `.exe` в `SHA256SUMS.txt`. Если репозиторий приватный, скачивание доступно только пользователям, которым владелец предоставил доступ.

## Что реализовано

- Регистрация и вход; пароли хешируются scrypt, сервер хранит только хеши токенов сессий.
- Друзья по личному коду с подтверждением заявки.
- Выбор игры, даты, времени, часового пояса, длительности и конкретных друзей.
- Приглашения, принятие / отказ, статусы всех участников, отмена организатором.
- Чат каждой встречи; встречу и сообщения видят только приглашённые участники.
- Центр уведомлений, Windows-уведомления из фонового процесса в трее.
- Серверная очередь FCM с повторными попытками и напоминаниями за 15 минут. Мобильные push включаются после настройки Firebase / APNs.
- Нативный календарь Android и iOS: добавление после принятия, защита от повторного добавления через локальный идентификатор, удаление при отказе или отмене после следующего открытия приложения. Нужны разрешения пользователя и доступный календарь для записи.
- `.ics` с временем UTC и напоминанием для импорта на Windows; импортированный файл сам не обновляется.
- Адаптивный русскоязычный интерфейс с авторскими SVG-иллюстрациями.

## Быстрый запуск

Установить Node.js **24+** и pnpm **11.25.0**. Из корня проекта:

```sh
pnpm install
pnpm dev
```

Интерфейс: `http://127.0.0.1:5173`, API: `http://127.0.0.1:3001`.
Войти кнопкой «Посмотреть локальное демо». Создаются Саша, Никита, Аня и Макс с примерными встречами. Демо-логины: `demo`, `nikita`, `anya`, `max`; пароль для всех: `partyup-demo`. Эти аккаунты общие, их данные не приватны. Режим демо включён только командой разработки, не production-сервером. Данные находятся в `data/partyup.sqlite`.

Окно Windows для разработки:

```sh
pnpm dev:desktop
```

Проверки и переносимая Windows-сборка:

```sh
pnpm test
pnpm build
pnpm package:win
```

Результат: `release/PartyUp-0.1.2-Windows.exe`. Это portable-сборка; она не включает общий сервер и не подписана сертификатом издателя. Для долгосрочного использования лучше выпустить подписанный установщик с постоянным путём: автозапуск portable-файла зависит от его расположения.

Обычный запуск API без демо: скопировать `.env.example` в `.env`, затем `pnpm server`.
На каждом устройстве ввести один и тот же HTTP- или HTTPS-адрес сервера. `localhost` на телефоне означает сам телефон, а не компьютер.

## Android

Нужны Android Studio 2025.2.1+, Android SDK (API 36 для сборки) и JDK, поставляемый со Studio. Android-проект уже создан.

```sh
pnpm mobile:android
pnpm exec cap open android
```

В Android Studio собрать debug APK для проверки на телефоне. Release APK / AAB требует собственного ключа подписи. Минимальные версии платформ задаются сгенерированным Capacitor 8 проектом в `android/variables.gradle`.

Нативный модуль: `android/app/src/main/java/com/partyup/app/PartyNativePlugin.java`. Сессия шифруется ключом Android Keystore. События записываются через Calendar Provider в первый видимый календарь с доступом на запись; приоритет — основной. Запрашиваются `READ_CALENDAR` и `WRITE_CALENDAR`, чтобы обновлять/удалять собственные события. Другие события на сервер не передаются.

## iOS

Нужны **Mac и Xcode 26+**. iOS-проект создан, но сборка и проверка на устройстве требуют macOS.

```sh
pnpm mobile:ios
pnpm exec cap open ios
```

В Xcode выбрать свою команду подписи и уникальный Bundle Identifier, если будете публиковать приложение. После изменения ID аналогично обновить `capacitor.config.ts`, Android applicationId и Firebase-приложения. Для установки на реальные устройства / TestFlight настроить подпись Apple.

Нативный модуль и регистрация моста находятся в `ios/App/App/AppDelegate.swift`; storyboard использует `PartyBridgeViewController`. Сессия хранится в Keychain. EventKit запрашивает полный доступ к календарю, потому что write-only не позволяет читать идентификатор события для обновления или удаления. Сохраняются и удаляются только события, идентификаторы которых создало приложение. Причины доступа указаны в `Info.plist`.

`scripts/native-setup.mjs` синхронизирует проект и создаёт локальную копию исходников FCM-плагина с уникальным именем директории для Swift Package Manager. Это устраняет конфликт идентичности пакетов и необходимость символических ссылок на Windows. Директория `vendor` генерируется из установленного пакета и не должна редактироваться вручную.

## Настройка мобильных push

1. Создать Firebase-проект и зарегистрировать Android и iOS приложения с нужными package / bundle ID.
2. Поместить `google-services.json` в `android/app/`; `GoogleService-Info.plist` — в `ios/App/App/` и добавить этот plist в target App через Xcode (Copy Bundle Resources). Эти файлы исключены из Git.
3. Для iOS загрузить APNs Auth Key в Firebase Cloud Messaging и включить Push Notifications capability в Xcode. Background Modes → Remote notifications и development entitlement уже подготовлены; для дистрибуции использовать production APNs окружение и профиль подписи.
4. Скачать закрытый ключ сервисного аккаунта Firebase Admin. Хранить вне Git, доступ только владельцу сервера. Указать путь в `GOOGLE_APPLICATION_CREDENTIALS` для API и перезапустить сервер. В контейнере путь должен быть `/run/secrets/firebase-admin.json` при файле `secrets/firebase-admin.json` на хосте.
5. Выполнить `pnpm mobile:android` / `pnpm mobile:ios`, пересобрать приложение. В настройках приложения включить мобильные push на **каждом** устройстве и разрешить уведомления.

Закрытое мобильное приложение получает уведомления через FCM/APNs. Android после принудительной остановки приложения системой/пользователем может не доставлять push до следующего запуска; применяются системные ограничения и настройки энергосбережения. Запись в календарь происходит после принятия приглашения в открытом приложении, а не из фонового push. Отмены синхронизируются при следующем открытии. Уведомления на Windows работают, пока фоновый процесс находится в трее; команда «Завершить работу» прекращает их получение. Это не WNS-доставка в полностью завершённый процесс.

## Где держать общий сервер

Для небольшой группы я рекомендую **один небольшой VPS с Docker и постоянным диском**. Это простой путь к доступу с мобильного интернета: один API, одна SQLite-база, Caddy для HTTPS. Начальная оценка ресурсов — 1 vCPU и 1 GB RAM; это проектная оценка, не результат нагрузочного тестирования. Резервные копии обязательны. Запускать **один** экземпляр API с SQLite на локальном диске, не на сетевом ресурсе.

Варианты:

- **Домашний ПК / мини-сервер / NAS.** Нет отдельной платы за VPS, но компьютер должен работать постоянно. Нужен доступ извне: публичный IP с пробросом порта, туннель либо согласованный VPN на всех устройствах. CGNAT может потребовать туннель или VPS. Версия 0.1.2 поддерживает HTTP по IP без домена и сертификата; при этом пароли, сообщения и токены сессий передаются без шифрования.
- **VPS в подходящем регионе.** Ориентир бюджета для планирования — эквивалент нескольких сотен рублей в месяц плюс домен и резервные копии. Это не котировка провайдера; проверить цену, доступность регистрации и способы оплаты перед заказом. Ничего платного не заказано.
- **Управляемая платформа с постоянным диском.** Уменьшает обслуживание, но засыпание бесплатных инстансов нарушает своевременные напоминания. Нужен постоянно работающий процесс и persistent volume. На ephemeral/serverless диск SQLite переносить нельзя. При масштабировании — PostgreSQL и отдельный планировщик/очередь; для компании друзей это обычно лишнее.

Сервер нужен для доступности с разных устройств. Полностью локальные независимые копии приложений без общего сервера не смогут обмениваться приглашениями через интернет. В домашнем варианте мастер-сервером становится один постоянно включённый компьютер.

### Windows + HTTP по IP

Для небольшого общего сервера установить Node.js 24 и скачать исходники в постоянную папку, например `C:\PartyUp`. Без мобильных push сервер использует только встроенные модули Node.js: установка зависимостей и сборка интерфейса на серверном ПК не нужны.

В PowerShell из папки проекта:

```powershell
Copy-Item .env.http.example .env
node --env-file=.env server/index.mjs
```

Шаблон включает `HOST=0.0.0.0`, `PORT=3001`, `DATA_DIR=./data`, `DEMO_MODE=false`. Копирование выполнять при первой настройке: существующий `.env` с настройками заменять не нужно. Сначала проверить `http://127.0.0.1:3001/api/health` на самом сервере; ответ содержит `"ok":true`. Разрешить входящий TCP 3001 для Node.js в брандмауэре Windows. Для доступа через интернет закрепить локальный IP компьютера в роутере и перенаправить внешний TCP 3001 на TCP 3001 этого ПК. У провайдера должен быть белый IP с доступными входящими подключениями; при CGNAT одного проброса порта недостаточно.

В клиентах **0.1.2 или новее** указать `http://<белый-IP>:3001` без `/api` и других путей. В одной домашней сети можно использовать `http://<локальный-IP-ПК>:3001`. При HTTP приложение показывает предупреждение на входе и в настройках. Использовать отдельный пароль для PartyUp: HTTP не защищает пароль, сообщения и токен входа от перехвата или подмены. HTTPS также поддерживается.

Отключить сон ПК и настроить запуск Node.js при загрузке через Планировщик заданий: программа `C:\Program Files\nodejs\node.exe`, аргументы `--env-file=.env server/index.mjs`, рабочая папка проекта. Выполнять независимо от входа пользователя, перезапускать при сбое, убрать ограничение времени выполнения. После настройки проверить сервер с мобильного интернета и после перезагрузки ПК. При изменении внешнего IP адрес в клиентах нужно обновить.

HTTP разрешён и в нативных проектах Android / iOS; API-запросы проходят через CapacitorHttp. Для iOS настройка `NSAllowsArbitraryLoads` может требовать обоснования при App Store Review. Проверка на физических телефонах и пересборка APK / IPA остаются необходимыми.

### Docker + HTTPS

Подготовить Linux-хост с Docker Compose, домен с A/AAAA-записью на этот хост и доступные TCP 80/443. В `.env` указать `PARTYUP_DOMAIN=party.example.com`. Для push добавить путь к закрытому ключу, как описано выше. Создать папку `secrets`, даже если push пока не настроены.

```sh
docker compose up -d --build
docker compose logs --tail=100 api
```

Caddy получает HTTPS-сертификат. В клиентах адрес сервера: `https://party.example.com`. База находится в именованном томе `partyup_data`. На production демо всегда отключено. Перед общим доступом подготовить резервное копирование и обновления хоста; Docker-конфигурация пока не запускалась в этом окружении.

### Резервная копия

Локально: `node scripts/backup.mjs`. Для контейнера: `docker compose exec api node scripts/backup.mjs`. SQLite `VACUUM INTO` создаёт согласованную копию в `data/backups/`; скопировать её на другой диск/хост. Для восстановления остановить API, сохранить текущую базу и её WAL/SHM-файлы отдельно, восстановить копию как `partyup.sqlite` и запустить API. Сессионные токены в резервной копии остаются действительными до срока истечения; хранить копии как закрытые данные.

## Ограничения первой версии

Нет голосовых звонков, вложений, редактирования времени уже созданной встречи, восстановления пароля по почте, приглашений по ссылке и сквозного шифрования чата. Для изменения времени пока отменить встречу и создать новую. Авторизация — логин и пароль. Потерянный пароль потребует административного восстановления; публичную регистрацию для большого сообщества стоит расширить отдельным процессом восстановления и подтверждением аккаунтов.

Обновление интерфейса — опрос раз в 5 секунд; сервер также содержит authenticated SSE endpoint `/api/live`. Очередь push хранится в SQLite, поэтому перезапуск API не теряет задания. Напоминания отправляются только участникам со статусом «принято». Мобильные токены принадлежат пользователю, включая несколько устройств.

Выход и кнопка «Сменить сервер» работают без интернета: локальная сессия и данные аккаунта очищаются, фоновые запросы отменяются. Отзыв сессии на прежнем сервере и удаление мобильного push-токена выполняются по возможности и не задерживают выход. Если сервер недоступен, его сессия остаётся действительной до истечения срока, но приложение больше не хранит и не использует её токен. Адрес сервера меняется на экране входа. Запоздалые ответы прежнего сервера не восстанавливают старый аккаунт и не влияют на новую сессию.

## Проверено в этой среде

Прошли проверки TypeScript, production-сборка интерфейса и 22 теста Node: права доступа, заявки в друзья, приглашения, ответы, чат, отмена, ICS, дедупликация напоминаний, отзыв сессии, повторные попытки push с тестовым транспортом, часовые пояса (включая переходы DST), выход без доступного сервера и во время запуска, смена сервера и защита новой сессии от запоздалых ответов. Проверены HTTP / HTTPS адреса, отбрасывание посторонних протоколов и адресов с учётными данными, привязка сессии к протоколу и серверу, регистрация и запросы состояния с последующим отзывом сессии через настоящий HTTP-сервер.

Собрана portable Windows x64 версия **0.1.2** на Electron 45.4.1; проверены запуск нового `.exe` и отображение предупреждения HTTP. В предыдущей сборке 0.1.1 проверены подключение к API и восстановление защищённой сессии после перезагрузки окна, создание встречи, выбор друзей, отправка сообщения и принятие приглашения; мобильный макет проверен на ширине 390 CSS-пикселей. Android и iOS проекты синхронизированы с новым интерфейсом. Снимок предыдущей Windows-сборки: `test-results/partyup-windows.jpg`.

Мобильные разрешения, запись в системный календарь и реальная доставка FCM/APNs требуют проверки на физических устройствах после настройки. APK/IPA не собраны: в этой среде нет Android SDK, macOS и Xcode. Docker-развёртывание и реальные системные уведомления Windows отдельно не проверены.
