# Уведомления PartyUp на телефоне: инструкция администратору

Для компании друзей рекомендуем один постоянно работающий сервер и один Firebase-проект, к которому подключены сервер и все мобильные сборки. Встречи и чат остаются в SQLite вашего сервера; уведомления идут через Firebase Cloud Messaging (FCM), а на iPhone — далее через APNs. Сервер отправляет в push заголовок и текст уведомления, включая текст сообщения чата, и идентификаторы встречи/уведомления.

**Готовый APK 0.3.1 из релиза собран без Firebase. Для фоновых уведомлений его нужно пересобрать с настройками вашего проекта.** Это нельзя включить только настройкой сервера. Для Android сначала настройте сервер и APK; iPhone дополнительно требует Mac, Xcode и настройки Apple Developer. Браузерные Web Push в PartyUp не реализованы.

## 1. Подготовить Firebase

1. Создайте проект в [Firebase Console](https://console.firebase.google.com/). Используйте один и тот же project ID для серверного ключа и конфигурации приложений.
2. Зарегистрируйте Android-приложение с package name **`com.partyup.app`**. Скачайте `google-services.json`; он понадобится на машине сборки в `android/app/google-services.json`.
3. Для iPhone зарегистрируйте iOS-приложение с Bundle ID **`com.partyup.app`** (либо своим ID, согласованно изменённым в нативных проектах и `capacitor.config.ts`). Скачайте `GoogleService-Info.plist`.
4. В настройках проекта → Service accounts → Generate new private key получите JSON-ключ для сервера. Серверному аккаунту нужно право отправки FCM сообщений (например, роль Firebase Cloud Messaging API Admin). Убедитесь, что Firebase Cloud Messaging API (HTTP v1) включён для проекта.

Серверный JSON содержит закрытый ключ: храните его только на сервере с доступом его владельца/службы, вне Git и архивов релиза. Никогда не кладите его в APK, IPA или папку публичной раздачи. `google-services.json` и `GoogleService-Info.plist` — отдельные клиентские конфигурации; серверный ключ их не заменяет.

## 2. Включить отправку на сервере Windows / Node.js

В папке сервера установите Node.js 24+ и pnpm 11.25.0. Если без push сервер работал без зависимостей, теперь установите их:

```powershell
pnpm install --prod --frozen-lockfile --ignore-scripts
```

Сохраните серверный JSON, например в `C:\PartyUp\secrets\firebase-admin.json`. Добавьте в существующий `.env` абсолютный путь (прямые слеши допустимы):

```dotenv
GOOGLE_APPLICATION_CREDENTIALS=C:/PartyUp/secrets/firebase-admin.json
```

Перезапустите API. При скрытом запуске — `Stop-Server.vbs`, затем `Start-Server.vbs`; если он работает через Планировщик — перезапустите задачу. При ручном запуске:

```powershell
node --env-file=.env server/index.mjs
```

Откройте `http://127.0.0.1:3001/api/health` (или свой порт): должно быть `"ok":true,"pushConfigured":true`. В логе запуска будет `push configured`. Это подтверждает подключение транспорта, но **не** проверяет ключ, его права и реальную доставку: это проверяется шагом 5. `pushConfigured:false` — процесс не увидел переменную; ошибки импорта — не установлены зависимости; ошибки чтения — неверный путь или права.

API должен быть постоянно запущен, ПК не должен засыпать. Нужен исходящий HTTPS-доступ к сервисам Google для авторизации и отправки FCM. На телефоне сервер должен быть доступен по мобильному интернету или через ваш VPN. Для публикации API используйте HTTPS; HTTP по IP поддерживается, но передаёт пароль и токен открытым текстом.

## 3. Собрать Android APK

На машине сборки нужны **полные исходники**, Node.js 24+, pnpm 11.25.0, JDK 21+ и Android SDK 36 / Build Tools 36.0.0. Один серверный ZIP не содержит нативных проектов и скрипта сборки Android.

1. Положите клиентский `google-services.json` в `android/app/`. Проверьте package name `com.partyup.app` и project ID.
2. Из корня исходников выполните:

```powershell
pnpm install --frozen-lockfile
pnpm mobile:android
powershell -ExecutionPolicy Bypass -File scripts/package-android.ps1
```

Если JDK/SDK не лежат в локальном `release/android-build-tools`, задайте `JAVA_HOME` и `ANDROID_HOME`. Результат — `release/PartyUp-0.3.1-Android.apk`. Устанавливайте эту сборку всем пользователям, которым нужны push. Телефону нужны совместимые Google Play services и доступ к FCM; для устройств без сервисов Google альтернативный push-транспорт здесь не реализован.

Скрипт подписи использует `secrets/android-release/partyup-release.p12` и `signing-password.txt`, создаёт их только при первом запуске. Сохраните закрытую резервную копию и используйте один ключ для следующих обновлений. Самостоятельно созданный ключ отличается от ключа официального APK: установить такую сборку поверх официальной нельзя. Потребуется удалить прежнее приложение (локальные настройки и вход потеряются; аккаунт и встречи на сервере сохранятся). Не передавайте закрытый ключ другим пользователям: им нужен только подписанный APK.

## 4. Включить на каждом телефоне

Откройте собранное приложение, укажите общий адрес сервера и войдите. В **Настройки → Рабочий стол и уведомления → Мобильные push** включите переключатель и разрешите системный запрос. Должно появиться «Push подключены». Переключатель включается отдельно на каждом устройстве. Если он недоступен, проверьте `pushConfigured` на сервере; если включение завершается ошибкой — клиентскую конфигурацию, разрешения и Google Play services / APNs.

На Android в системных настройках PartyUp разрешите уведомления и канал «Игровые встречи», проверьте звук и режим «Не беспокоить». При задержках проверьте ограничения фоновой работы и энергосбережения производителя. После «Принудительно остановить» снова откройте приложение перед тестом.

Для напоминаний дополнительно включите **Настройки → Будильник перед встречей**, выберите число минут и нажмите «Сохранить». Будильник синхронизируется между устройствами аккаунта. С версии 0.3.1 напоминание отправляется только когда **все приглашённые согласились**: ожидающий ответа или отказавшийся участник блокирует его для всей команды. После переноса встречи все гости должны принять новое время. Если команда собралась уже внутри выбранного интервала, напоминание будет создано при следующей проверке до начала встречи (обычно в течение 10 секунд). После начала опоздавшие напоминания не создаются.

## 5. Проверить доставку

1. Подготовьте два аккаунта на одном сервере и добавьте их в друзья. Телефон с включёнными push сверните, заблокируйте экран.
2. С другого аккаунта создайте встречу и пригласите владельца телефона: должно прийти приглашение. Нажатие должно открыть встречу.
3. Примите приглашение всеми участниками. Включите будильник за 5 минут и создайте/перенесите встречу на 3–4 минуты вперёд; после переноса подтвердите участие заново. Дождитесь проверки планировщика, оставив телефон заблокированным.
4. Для проверки ограничения создайте ещё одну близкую встречу и оставьте одного гостя без ответа: напоминаний быть не должно. Приглашения, ответы и сообщения чата не требуют согласия всей команды.

Если сообщения видны только после открытия приложения, проверяйте реальный APK с Firebase, одинаковый project ID, включённые push и системные разрешения. При `Push delivery failed` в `logs/server-error.log` (или консоли/логах контейнера) проверяйте серверный ключ, разрешение отправки, API и исходящую сеть. Ошибки `SENDER_ID_MISMATCH` / mismatched credential обычно означают разные Firebase-проекты. После исправления проекта выключите/включите push на телефоне для повторной регистрации. Очередь хранится в SQLite и повторяет временные ошибки; она не обходит ограничения системы телефона.

## iPhone

На Mac поместите `GoogleService-Info.plist` в `ios/App/App/` и добавьте в target App → Copy Bundle Resources. Выполните `pnpm install --frozen-lockfile`, `pnpm mobile:ios`, `pnpm exec cap open ios`. В Xcode выберите свою команду подписи и соответствующий Bundle ID, включите **Push Notifications** и **Background Modes → Remote notifications**. Проверьте entitlement `aps-environment` и профиль подписи: development для разработки, production для распространения.

В Firebase → Project settings → Cloud Messaging → настройки iOS загрузите APNs authentication key из Apple Developer и укажите Key ID / Team ID согласно форме. Соберите подписанное приложение и установите на реальный iPhone / через TestFlight; готового IPA в релизе нет. В PartyUp включите «Мобильные push», в настройках iOS разрешите уведомления/звуки и проверьте Focus и сводку уведомлений. Повторите шаг 5 на заблокированном телефоне. Этот путь требует проверки на физическом устройстве; наличие исходников не подтверждает доставку APNs.

## Docker из полного репозитория

Положите ключ на хосте в `secrets/firebase-admin.json`. В `.env` рядом с `compose.yaml` задайте:

```dotenv
PARTYUP_DOMAIN=party.example.com
GOOGLE_APPLICATION_CREDENTIALS=/run/secrets/firebase-admin.json
```

В контейнер передаётся **путь внутри контейнера**. Compose монтирует `./secrets` только для чтения; пользователь `node` внутри контейнера должен иметь право чтения ключа. Выполните `docker compose up -d --build`, проверьте `docker compose logs --tail=100 api` и `https://party.example.com/api/health`. Клиентскую сборку и шаги 4–5 всё равно нужно выполнить.
