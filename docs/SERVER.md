# Сервер PartyUp 0.3.1

Нужен Node.js 24+. Сервер общий для всех участников; Windows-клиент запускается отдельно. Распакуйте архив в постоянную папку.

## Первый запуск в Windows

В PowerShell из папки архива:

```powershell
Copy-Item .env.http.example .env
node --env-file=.env server/index.mjs
```

Проверьте `http://127.0.0.1:3001/api/health`. Демо отключено. Без мобильных push установка зависимостей не требуется. Разрешите входящий TCP-порт 3001 в брандмауэре; для доступа через интернет нужны доступный внешний IP и проброс порта либо общий VPN/туннель. Клиенты указывают один адрес `http://<IP-сервера>:3001`. HTTP передаёт данные без шифрования; для HTTPS разместите API за обратным прокси с сертификатом.

Для поиска Steam серверу нужен исходящий HTTPS-доступ к `store.steampowered.com`; для обложек — доступ клиентов к Steam CDN. Ключ API не нужен. При сбое поиска можно ввести игру вручную.

## Запуск без окна в Windows

После создания `.env` дважды нажмите **Start-Server.vbs** в корне архива. Сервер работает без окна PowerShell или консоли Node.js. **Stop-Server.vbs** останавливает процесс, запущенный этим способом. Права администратора для запуска не нужны; Node.js 24+ должен быть доступен в PATH.

Если Windows Script Host / VBScript отключён, используйте PowerShell:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\server-windows.ps1 -Action Start
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\server-windows.ps1 -Action Status
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\server-windows.ps1 -Action Stop
```

Команда запуска завершается, сервер остаётся скрытым. Повторный запуск через скрипт не создаёт второй экземпляр. Состояние процесса хранится в `.partyup-server`; stdout и ошибки — в `logs/server.log` и `logs/server-error.log`. При следующем запуске прежние логи копируются в файлы с суффиксом `.previous`. После запуска проверьте `/api/health`: сообщение о запуске процесса само по себе не проверяет доступность сервера с телефона. В случае ошибки VBS показывает сообщение; запустите команду Start в PowerShell, чтобы увидеть причину.

Скрипт управляет только своим процессом. Если сервер ранее запущен вручную или через Планировщик, сначала остановите его соответствующим способом. Не запускайте одновременно несколько API с одной базой. При закрытии сеанса Windows, сне или выключении ПК доступность сервера прекращается.

Для работы после перезагрузки и без входа пользователя создайте задачу в **Планировщике заданий**: триггер «При запуске», программа — полный путь к `node.exe`, аргументы — `--env-file=.env server/index.mjs`, поле «Рабочая папка» — постоянная папка сервера. Выберите «Выполнять вне зависимости от регистрации пользователя», настройте перезапуск при сбое, уберите ограничение времени и отключите сон ПК. Такой запуск не открывает интерактивную консоль. Для автозапуска используйте непосредственно Node.js: задача должна следить за самим API. Останавливайте его через Планировщик. Проверьте `/api/health` после перезагрузки.

## Обновление с 0.2.0 / 0.3.0

1. С текущими настройками создайте копию: `node --env-file=.env scripts/backup.mjs`. Сохраните полученный файл из `data/backups` на другом диске; при своём `DATA_DIR` используйте соответствующую папку.
2. Остановите процесс сервера: `Stop-Server.vbs` для скрытого запуска, Ctrl+C для консоли или остановка задачи в Планировщике.
3. Замените папки `server`, `scripts` и файлы `package.json`, `pnpm-lock.yaml`, `pnpm-workspace.yaml` файлами из архива. Скопируйте `Start-Server.vbs`, `Stop-Server.vbs`, `SERVER.md`, `MOBILE-PUSH.md`. Сохраните свои `.env`, `data`, секреты Firebase и путь `DATA_DIR`.
4. Запустите `node --env-file=.env server/index.mjs`. Дополнительные поля SQLite создаются автоматически. Аккаунты, встречи и чат сохраняются.
5. Обновите клиенты до 0.3.1. Проверьте вход и существующие встречи. Схема базы 0.3.0 не меняется. Напоминания появляются только после согласия всех приглашённых; после переноса времени нужно повторное согласие каждого гостя.

Для отката остановите API, сохраните текущие файлы SQLite/WAL/SHM отдельно и восстановите резервную базу вместе с предыдущими исходниками. Не копируйте одну живую SQLite-базу обычным копированием при работающем API.

## Мобильные push

По умолчанию выключены. **[Пошаговая инструкция для администратора и пользователей](MOBILE-PUSH.md)** входит в этот архив. Нужны Firebase на сервере и мобильная сборка того же Firebase-проекта; готовый APK 0.3.1 не содержит настройки Firebase. Одного включения переменной на сервере недостаточно.

Сервер должен работать постоянно. Запускайте один экземпляр API с SQLite на локальном постоянном диске. Настройте автозапуск, перезапуск при сбое и резервные копии.
